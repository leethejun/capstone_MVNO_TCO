# 알뜰폰허브 전체 브랜드관 수집 점검

## 발견한 구조 문제

전역 요금제 수집기 `MvnohubCrawler`는 전체 페이지를 순회하고 있었다. 반면 `DirectTelecomCrawler`의 별도 브랜드관 수집 경로는 첫 HTML 페이지의 최대 12개 카드만 읽었다. 모빙에 적용한 전체 페이지 검증을 다른 브랜드에도 확대했다.

기존 전역 수집과 브랜드관 수집은 같은 허브 상품을 서로 다른 제목과 출처로 저장할 수 있었다. 특히 브랜드관 경로가 `[브랜드특가]` 접두사를 붙여 전역 목록의 같은 상품과 중복됐다. 프리티는 LGU+ 브랜드관과 SKT·KT 브랜드관 두 개를 모두 보존해야 하며, 통신사별 관리자 행은 하나로 묶어야 한다.

## 수정 내용

- 허브의 현재 24개 통신사·25개 브랜드관을 모두 공통 `HubBrandCrawler`로 처리한다.
- API의 전체 상품 수, 전체 페이지 수, 현재 페이지와 다음 페이지 여부를 확인한다.
- 각 페이지 API 상품 ID와 HTML 카드 ID를 대조한다. 브랜드 페이지 수는 처음 보이는 숫자 버튼으로 추정하지 않는다.
- 모든 상품의 상세 스펙을 읽어 목록에서 생략된 일일 데이터와 QoS 등을 복원한다.
- 가격은 현재 납부액과 할인 종료 후 요금을 구분하며, 상시 할인은 종료 후에도 유지한다.
- 빈 브랜드관은 API와 HTML이 모두 빈 목록일 때만 정상 0개로 인정한다.
- 전역 목록과 브랜드 목록은 허브 상품 ID로 합친다. 전체 검증을 완료한 통신사는 최신 브랜드 스냅샷을 우선하고, 브랜드관이 없는 통신사의 전역 상품은 유지한다.
- 다른 상품 ID를 가진 판매 상품은 스펙과 가격이 같아도 별도로 보존한다.
- 프리티의 두 브랜드관은 모두 수집하고, 관리자에서는 한 통신사 행으로 합산한다.
- 브랜드 목록 탐색이 일시 실패해도 확인된 25개 공개 브랜드관 링크를 사용할 수 있다.
- 어느 브랜드든 전체 허브 검증에 실패하면 통합 DB 교체를 중단한다.

상세 요청은 동시에 최대 2개를 처리하며 기본 요청 시작 간격을 0.15초 이상 유지한다. 인증서 검증은 유지한다. 기존 금융 조건 상품 제외 정책과 사용자 지정 통신사 제외 목록은 유지한다.

## 실행과 감사 추적

```bash
# 전체 브랜드 목록과 상품 상세 감사. DB는 변경하지 않는다.
docker exec alddle_backend python -B -m deploy.audit_hub_brands
# 이미 저장한 공개 응답으로 재검증하고 미수집 응답은 추가 조회한다.
docker exec alddle_backend python -B -m deploy.audit_hub_brands --resume runtime/hub-brand-audit-20261103-125104
# 전역 목록과 브랜드 상품 ID가 일치하고 모든 브랜드가 완료되어야 반영 가능하다.
docker exec alddle_backend python -B -m deploy.refresh_hub_snapshot runtime/hub-brand-audit-20261103-125104 --apply
```

반영 전 전체 상품과 관리자 보고서를 백업한다. 운영 갱신은 허브 상품만 대상으로 하며 공식몰 상품은 유지한다. 과거 상품은 비활성 이력으로 남기고 동일한 상품을 재실행하면 기존 행을 재사용한다.

실제 공개 응답, 통신사별 검증 원본, 전역 수집 결과는 `runtime/hub-brand-audit-20261103-125104/`에 저장한다. 재사용한 응답은 이번 조사에서 직접 받은 같은 시점의 공개 원본이며 과거 조사 자료를 현재 상품으로 전환한 것이 아니다.


## 최종 검증과 운영 반영

24개 통신사에 연결된 25개 브랜드관 전부 검증을 통과했다. 전역 HTML 목록은 67페이지까지 확인했고, 마지막 전역 전체 API 응답의 고유 상품 ID 795개가 브랜드관 전체 상품 ID 795개와 정확히 일치했다. 페이지 누락과 상품 ID 중복은 없다.

조사 중 이지모바일 상품 수가 60개에서 66개로 증가했다. 기존 페이지와 새 페이지를 섞은 응답은 거부하고 해당 브랜드관을 새로 조회했다. 목록 전체를 먼저 확정한 뒤 상세를 읽도록 처리 순서도 변경했다. 목록 변경 감지 시 전체 스냅샷을 최대 3회 재시도하며, 최종 실패 시 기존 DB를 보존한다.

일부 무제한 상품에서 상세 표의 속도 행이 생략되는 차이는 목록 카드와 API의 명시 속도가 일치할 때만 보완했다. 상품명의 매일 30분 같은 문구보다 상세의 월 통화량 900분을 우선하도록 공통 파서도 보강했다.

기존 행 수에는 첫 페이지 중복과 과거 수집 시점 차이가 포함된다. 감소한 수치를 미수집으로 해석하면 안 된다. 프리티는 두 브랜드관 36개와 66개를 합친 102개이며 관리자에서는 한 행으로 표시한다. 0개인 곳은 통신사 전체 상품이 없는 것이 아니라 허브 공개 판매 목록이 없는 경우이며 공식몰 상품은 유지했다.

- 허브 활성 상품 722개에서 795개로 갱신했다.
- 공식몰 활성 상품 3,443개를 유지해 전체 활성 상품은 4,238개다.
- 허브 상품 83개에서 일일 추가 데이터를 확인했다.
- 24개 통신사의 6/12/48개월 운영 랭킹 API 72건이 모두 HTTP 200이었다.
- 기존 제외 통신사는 관리자 목록에 나타나지 않으며, 관리자 통신사 행은 중복 없이 47개다.
- 백엔드 unittest 175개가 통과했다. 백엔드를 재시작해 관리자 및 정기 수집 경로에 적용했다.
- 적용 전 백업과 실행 결과는 `runtime/hub-brand-audit-20261103-125104/apply-20261103-132011/`, 사후 ID 대조 및 API 검증은 같은 감사 폴더의 `verification.json`에 있다.
