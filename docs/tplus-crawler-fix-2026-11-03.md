# 티플러스 공식몰 수집 수정과 검증

## 원인

기본 Requests 연결에서 `SSL: WRONG_SIGNATURE_TYPE`가 재현됐다. 티플러스 전용 SSL 컨텍스트의 TLS 1.2 암호군을 `AES128-GCM-SHA256:AES256-GCM-SHA384`로 지정하면 공식 apex 호스트에 접속할 수 있었다. CA 신뢰 체인, 호스트 이름, 유효기간 검증 및 기본 OpenSSL 보안 수준은 유지한다. 검증 비활성화, 전역 SSL 설정 변경, 보안 수준 하향을 사용하지 않는다. 이 설정은 티플러스 요청에만 적용한다.

`www.tplusmobile.com`은 조사 시 HTTP 400을 반환했다. 정상 응답하는 `https://tplusmobile.com`을 사용한다. 요금제 목록은 정적 HTML이 아니라 공식 화면이 호출하는 `/BackBone/rate/rate_list` POST 응답에 있으므로 전용 수집기를 추가했다.

## 수집과 가격 검증

- 공식 화면의 전체 요금제 조건과 동일한 필터 범위를 사용한다.
- 첫 페이지 `F`, 후속 페이지 `N`과 서버 커서로 목록을 순회한다.
- 전체 수, 페이지별 카드 수, 상품 코드 중복, 커서 반복을 검사한다.
- 상품권 등을 뺀 혜택 체감가를 월 납부액으로 사용하지 않는다.
- 취소선 가격과 할인 종료 후 청구액이 다르면 명시된 종료 후 청구액을 사용한다.
- `4개월 후 평생`은 4개월 할인으로 처리한다. 처음부터 평생 할인인 상품과 구분한다.
- 평생 상품의 미공개 정상가는 NULL과 미확인 마커로 보존한다.
- 일일 데이터만 있는 상품은 월 기본 데이터 0GB와 일일 데이터로 분리한다.
- 외국인 전용, 시니어, 복지, 태블릿 상품은 일반 환승 추천에서 제외한다.

## 실제 확인 결과

2026년 11월 3일 한국 시간 기준 공식 전체 목록 243개를 13페이지에서 확인했다. 제외 대상 7개를 제외한 236개가 검증을 통과했으며 파싱 실패는 0개다. 일반 기간 할인, 4개월 후 평생 요금, 정상가 미공개 평생 상품의 상세 페이지도 대조했다.

`python -B -m deploy.refresh_tplus --apply`로 공식몰 상품만 갱신했다. 적용 전 티플러스 DB와 관리자 보고서를 백업했다. 기존 허브 상품 52개를 유지해 활성 상품은 합계 288개가 됐다. 구독 상품 이력은 공통 교체 함수의 보존 정책을 따른다.

- 실행 원본, 적용 전 백업 및 결과: `runtime/tplus-refresh-20261103-114613/`
- 관리자 보고서: 티플러스 `official_count=236`, `status=collected`, `error=null`
- 과거 전체 실행 시각은 보존하고 티플러스 부분 갱신 시각을 별도 기록했다.
- 백엔드 컨테이너를 재시작해 관리자·정기 수집에도 전용 수집기를 적용했다.
- 운영 랭킹 API는 6/12/48개월 모두 HTTP 200, 공식몰 상품 반환을 확인했다.
- DB 공식몰 상품 236개 모두 6/12/48개월 TCO 랭킹 계산 대상임을 확인했다.
- 신규 회귀 테스트 9개와 백엔드 전체 unittest가 통과했다.

## 재확인 명령

```bash
docker exec alddle_backend python -B -m unittest discover -s tests -p test_tplus_crawler.py -v
# 검증과 결과 저장만 실행
docker exec alddle_backend python -B -m deploy.refresh_tplus
# 백업 후 티플러스 공식몰 상품만 반영
docker exec alddle_backend python -B -m deploy.refresh_tplus --apply
```
