# 수집 제외와 아시아모바일 모빙 우리WON 확인

2026년 11월 3일 사용자 요청으로 스노우맨, 니즈모바일, 친구모바일, 아이디스파워텔, 서경모바일, 여유모바일, 원텔레콤을 마스터에서 제거했다. 이름과 공식 도메인으로 제외하며 허브에서 재발견해도 수집 대상으로 복귀하지 않는다. 관리자 과거 보고서와 메모리 결과에도 동일 필터를 적용한다. 기존 구독 참조를 위해 통신사 DB 행은 보존하며 일반 통신사 목록에서는 숨긴다. 이번 확인에서 해당 7곳의 활성 상품은 모두 0개였다. 마스터 동기화 시 제외 사업자 상품을 비활성화하는 처리도 추가했다.

## 아시아모바일

기존 범용 수집은 onclick 기반 메뉴와 별도 API를 인식하지 못했다. 현재 공식 메뉴는 `/view/price/pricePlan.aspx`, 목록 요청은 `/common/component/price/AjaxPricePlan.aspx`다.

전용 수집기로 전체 후불 목록과 KT 및 LGU+별 목록을 교차 검증한다. 전체 응답 115행은 카테고리 중복을 포함해 고유 상품 58개로 정리된다. 복지·시니어 3개를 제외한 55개가 검증을 통과했고 누락 파싱은 0개다. 할인액은 부가세를 포함해 계산하고, 실제 표시 납부액 REAL_AMT와 대조한다. 내부 DATAAMOUNT 대신 화면 스펙 SEEDATA를 사용한다.

공식몰 55개를 운영 DB에 반영했고 기존 허브 64개는 유지했다. 활성 상품은 합계 119개다. 백업과 결과는 `runtime/asia-refresh-20261103-120232/`에 있다. 6/12/48개월 운영 랭킹 API가 모두 HTTP 200을 반환하고 공식몰 상품을 포함했다.

관리자의 기존 허브 12개는 브랜드 페이지 첫 화면 건수였으며 전체 허브 수집량이 아니었다. 파이프라인 보고서는 전체 허브와 브랜드관의 실제 적재 건수를 합산하도록 수정했고 기존 보고서도 DB 기준으로 재집계했다.

## 우리WON모바일

현재 공식 API 47개를 재조회했으며 기존 정책으로 수집 1개, 제외 46개, 파싱 실패 0개였다. 제외 46개는 금융 조건 26개와 가입 대상·추가 혜택 조건 20개다. 이번에는 조건부 상품을 제외하는 정책을 변경하지 않았다. 단순히 사이트에 상품이 1개라는 의미가 아니므로 관리자 표시용 검토 수와 제외 사유를 추가했다. 상세 및 결과의 조사 원본은 이번 컨테이너 임시 경로에 보관했고 보고서에는 집계만 반영했다.

## 모빙 미해결 사항

기존 수집 코드가 폐기된 `/plan/list`를 요청하고 할인 기간을 임의로 12개월로 설정하고 있었다. 사용자 제공 현재 주소 `/product/plan`으로 경로를 수정하고 고정 할인 기간 추정을 제거했다. 접속/파싱 실패를 숨기지 않고 구체적인 오류를 관리자 보고서에 남긴다.

하지만 이번 실행 환경에서는 현재 주소도 Requests, urllib, 호스트 curl, 내장 브라우저에서 연결이 종료됐다. 과거 `/main`은 HTTP 410 또는 연결 종료를 반환했다. 공개 DNS 조회는 현재 로컬 DNS 결과와 일치했다. 사이트 운영 종료나 서버의 의도적인 IP 차단으로 단정할 증거는 없다. 현재 네트워크에서 공식 목록 응답을 얻지 못해 새 목록 구조에 대한 파싱·전체 수집 성공은 검증하지 못했다. 활성 상품 0개 상태를 성공으로 바꾸지 않았다.

## 검증과 배포

### 모빙 추가 연결 진단 12시 12분

사용자는 일반 창의 기존 화면은 보이지만 시크릿 창과 Ctrl+Shift+R 강력 새로고침에서는 열리지 않는다고 확인했다. 따라서 일반 창의 기존 화면을 현재 공식몰 신규 응답 성공의 근거로 사용할 수 없다. 캐시 영향 가능성이 높으며 현재 서버만의 접근 실패로 단정할 수 없다.

별도 진단에서 DNS는 로컬·Google·Cloudflare 모두 `211.119.128.201`로 일치했다. TLS 1.3과 인증서 신뢰 체인·호스트 이름·유효기간 검증은 성공했다. HTTP/2 협상도 성공했지만 GET 후 연결이 reset됐다. HTTP/1.1에서는 요금제와 favicon 요청 모두 상태줄 없이 수신 0바이트로 연결이 종료됐다. 브라우저 계열 TLS 요청 특성, 기본 언어 쿠키, TLS 세션 재사용으로도 응답을 받지 못했다. 실제 사용자 인증·세션 쿠키는 요청하거나 사용하지 않았다.

확인 가능한 실패 지점은 TLS 뒤 HTTP 응답 이전이다. 외부에서만 관측한 결과로 모빙 웹서버 자체, 앞단 장비, 네트워크 중 어느 구성의 문제인지 확정하지 않는다. 공식몰에서 새 HTTP 응답을 확보하지 못했으므로 실제 HTML/API 파싱과 전체 상품 수집은 여전히 미완료다. 인증서 검증 하향, 과거 검색 캐시의 운영 상품 전환, 허위 성공 보고는 하지 않았다.

재현 도구는 `docker exec alddle_backend python -B -m deploy.audit_mobing_connection`이며 진단 원본은 `runtime/mobing-connection-20261103-121230.json`에 저장했다.

- 백엔드 unittest 157개 통과.
- 프론트엔드 빌드 성공, lint 오류 없음. 기존 경고는 남아 있다.
- 백엔드 재시작 완료. 관리자 API와 공개 통신사 목록에서 제외 7곳이 나타나지 않음을 확인했다.
- 관리자 보고서의 공식몰·허브 수치는 기존 프론트엔드에서도 즉시 반영된다.
- 프론트엔드의 활성 건수·부분 갱신일·제외 사유 추가 표시는 빌드까지 완료했다. `sudo bash deploy/update-frontend.sh`는 실행 환경의 `no new privileges`로 실패해 운영 정적 파일은 교체되지 않았다. 호스트에서 배포 스크립트를 실행해야 한다.
