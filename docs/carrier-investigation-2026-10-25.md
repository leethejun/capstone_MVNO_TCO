## 크롤러 보완

- 위너스텔은 기존 범용 수집에서 방문 순서/주소와 카테고리에 의존했다. 공식 전체 후불 5개 카테고리를 명시적으로 순회한다.
- 각 카테고리 응답·상품 코드·가격·기간을 검증하며 실패한 카드를 조용히 누락시키지 않는다.
- `;jsessionid=...`를 상품 URL에서 제거하여 실행마다 달라지는 세션 ID가 중복 상품을 만들지 않게 한다.
- BEST 등 같은 조건의 별도 공식 상품 코드는 임의로 합치지 않는다. 포인트·쿠폰은 월 청구액에서 차감하지 않는다.
- 페이지 분할 구조가 생기면 첫 페이지만 전체로 간주하지 않고 오류로 보고한다.
- 전체 수집 경로에도 전용 수집기를 연결했다. 다른 통신사 데이터·구독 이력은 수동 갱신에서 보존한다.

실행: `docker exec alddle_backend python -m deploy.refresh_well` (수집/검증만),
`docker exec alddle_backend python -m deploy.refresh_well --apply` (검증 후 위너스텔 공식 상품만 교체).
건수·제외 사유와 적용 결과는 `runtime/well-refresh.json`에 저장한다.

## 운영 보고서 문제

`runtime/crawler-report.json`에 `hub_crawled=1`, `total_active_plans=1`, `coverage=[]`인 테스트 데이터가 발견됐다.
실제 운영 DB와 다른 내용이었다. `test_kgmobile_crawler`의 파이프라인 테스트가 보고서 경로를 분리하지 않아 발생했으며,
해당 테스트의 출력 경로를 `/tmp/test-kg-pipeline-report.json`으로 분리했다.
테스트 전후 운영 보고서 SHA-256 불변을 확인했다. 이전 정상 전체 보고서는 이 파일로부터 복원할 수 없다.

## 검증

## 50개 미만 통신사 전수 재조사 (추가 작업)

기준은 **조사 시작 시 활성 요금제 50개 미만인 마스터 통신사 37곳**이다.
소규모 사업자여서 상품이 적을 것이라는 가정은 사용하지 않는다. 공개 메뉴의 전체 카테고리,
통신망 탭, 목록 API, 페이지 종료를 확인하고 미검증 항목을 별도로 남긴다.
아래 현재 건수는 허브와 공식몰 조건을 함께 포함하는 운영 DB 행 수이며 공식 원본의 고유 상품 수와 다르다.
50개 미만이라는 이유로 조사 완료 또는 정상 수집으로 판정하지 않는다.

### 실제 누락 원인과 보완

- KT M: 전체 카테고리 API를 순회해 157개 검증. 제휴 카테고리도 방문하되 결합·기기·연령 제한 상품을 구분한다. 조건부 24개월 추가 데이터를 기본 제공량에 합치지 않는다.
- 스카이라이프: 옛 쇼핑몰 주소 대신 공식 상단 메뉴의 새 전체 목록을 사용. Flight 전체 배열 211행의 코드 중복을 제거한 109개 중 108개 검증. 월 청구 주기 1개월을 프로모션 기간으로 해석하지 않는다.
- 스마텔: 공식 전체 상품 188개의 배열을 처리해 일반 가입 대상 158개 검증. 추가 혜택을 기본 데이터에 합치지 않는다.
- A모바일: `www` API는 빈 응답이지만 공식 메뉴가 연결하는 대표 도메인 `amobile.co.kr` API는 135개를 반환. 133개 검증. 일시 할인 종료 가격은 기본료에서 지속 할인액을 뺀 실제 청구액이다.
- 토스: 공식 화면 모듈의 공개 API가 반환하는 47개 중 46개 검증. 가입 가능 날짜와 가입 후 할인 개월 수를 구분한다.
- 이야기: 기존 HTML 예시 카드/일부 태그 수집을 제거. 전체 검색 API 322개(후불 298, 선불 24) 중 검증된 일반 상품 294개 수집. 7개월을 UI 분류인 `t12`로 오해하지 않으며 `restoration_fee`를 할인 종료 가격으로 사용한다.
- 인스·아정당·마블링·슈가·KCTV·온국민·토리: 첫 목록에서 끝내지 않고 메뉴의 모든 요금제 카테고리를 순회. 상품 코드와 세션 ID를 분리하고 상세 편집기 표의 정상가·지속 할인액을 처리한다. 아정당은 17개에서 145개로 증가했다.
- 유모바일·헬로: 기본 `requests` User-Agent는 각각 HTTP 410/400을 받았으나 표준 `urllib` 클라이언트는 정상 응답했다. 인증서 검증을 유지한 urllib 수집기로 교체했다. 유모바일 전체 목록 136개 중 130개, 헬로 API 150개 중 129개를 검증했다. 헬로의 '더보기'는 전체 API 배열을 화면에서 자르는 방식이므로 크롤러에서는 자르지 않는다.
- 밸류컴·퍼스트: 상단 메뉴뿐 아니라 `onclick` 통신망 탭과 페이지 링크도 순회한다. URL 쿼리 순서/인코딩을 정규화하고 상품 ID로 중복 제거한다. 퍼스트의 실제 공개 KT 목록 13개와 상세를 모두 재검증했으며, 이것만으로 다른 판매 경로가 없다고 단정하지 않는다.

### 적용·검증 상태

- 1차 추가 작업 반영 후 활성 상품 **4,057개**, 전체 4,059행(비활성 구독 이력 2개).
- 가격·기간을 모두 검증한 통신사만 공식몰 상품을 트랜잭션으로 교체했다. 허브 판매 조건 및 구독 이력을 보존한다.
- 미검증 통신사는 정상 수집으로 처리하지 않으며, `failed_telecom_names`에 검증 누락을 기록한다.
- 이번 조사는 전체 정기 크롤링 실행과 다르다. 과거 운영 전체 보고서 파일을 새 전체 성공 보고서로 꾸미지 않는다.
- 원본·초기 37곳 점검: `runtime/small-carrier-audit-2026-10-25/report.json` 및 하위 HTML/JSON.
- 수집·실제 적용 결과: 같은 폴더의 `verified-refresh.json`, `extra-refresh.json`, `db-after.json`.

- **인증서 오류·원본 가격 누락 등 미해결이 남아 있어 37곳 전부의 수집 누락 해소가 완료된 상태는 아니다.**

## 미해결 통신사 후속 조사 및 반영

### 드림라인: 외부 API 장애라는 이전 판단을 정정

실제 브라우저 전체 목록에서 28개가 정상 표시되는 것을 확인했다. 기존 요청은
`flatFgArr=[]`를 보냈지만 공식 화면의 기본 선택은 `flatFg_0`(종량제),
`flatFg_1`(정액제) 모두 active였다. `['0','1']`를 전달하면 `RESULT=Y`로 정상 응답한다.
페이지의 모든 요금 유형을 읽어 보내고 전체 28개 상품 코드를 대조한다.
후불 15개 중 제공량 없는 순수 종량제 '번호만 드림' 1개는 고정 사용량 TCO 대상에서 구분했다.
나머지 14개는 상품별 `type=02` 상세 응답의 코드·가격·제공량까지 일치 확인 후 반영했다.
템플릿 DREAM4의 19,900원을 사용하지 않으며 실제 API/브라우저의 DREAM 4 월 4,950원을 사용한다.

### 우리WON: TLS 체인 보완 및 금융 조건 검증

서버가 리프 인증서만 보내 중간 인증서 `GeoTrust EV RSA CA G2`가 누락됐다.
발급기관 DigiCert 공식 배포본을 기존 OS 루트 `DigiCert Global Root G2`로 검증했다.
개별 SSL 컨텍스트에 중간 인증서를 공급하며 호스트 이름·루트·유효기간 검증은 유지한다.
검증 비활성화/PARTIAL_CHAIN 플래그를 사용하지 않는다. 인증서 원본·지문은
`services/crawler/certificates/README.md`에 기록한다.

전체 45개 목록과 상품별 상세를 대조했다. `srvDesc`만 보는 대신 상품별 `bigo1Desc`~`bigo5Desc`까지
금융 조건을 확인한다. 셀럽 상품의 금융거래 조건은 `bigo5Desc`에 있었다.
금융상품 조건 44개를 제외했고, 조건 없는 첫 2개월이 명시된 500MB/50분 상품 1개를 재검증했다.
여러 상세 행이 있다는 이유로 금융 조건 상품을 '수집 실패'로 오인하던 보고도 보완했다.

### 에르엘: 할인 필드만으로 누락 판정하지 않음

공식 카드의 평생할인 표시가 `getCmTags`의 `soc_tag`와 상품 `tags` CSV에 따로 저장되어 있었다.
실제 '평생할인' 이름을 조회해 연결한 8개를 추가했다. 빈 할인 기간만으로 평생할인을 추정하지 않는다.
공식 공개 판매 화면의 25개 이름과 새 수집 결과 25개가 일치한다.
추가 API 상품 `LPZ0019765`(음성300분15GB+)는 해당 화면에 표시되지 않고 기간·태그 근거가 없어
추천에 넣지 않았다. API 데이터만 존재한다는 이유로 현행 공개 판매 상품으로 단정하지 않는다.

`dataDesc`는 월 데이터 숫자가 아니라 '소진 후 일2GB/최대3Mbps' 같은 보조 설명이었다.
월 데이터는 숫자 필드에서 읽고 일일 제공량과 QoS를 분리했다. 망내 1회선 무제한 혜택을
일반 음성 300분 전체 무제한으로 오인하지 않도록 기본 통화량을 사용한다.

### 한패스·밸류컴: 미공개 정상가를 가짜 가격으로 대체하지 않음

- 한패스는 전체 메뉴·24개 상세·약관·공식 다운로드·공지·가입 안내 첫 화면을 확인했다.
  평생할인 6개는 할인 전 요금이 공개되어 있지 않지만 월 청구액·평생 조건은 명시된다.
- 밸류컴은 모든 통신망 탭 17개를 확인했다. 상품 98은 공식적으로 '24개월 할인 후 49,5000원'이라는
  오기가 남아 있다. 월 39,600원과 할인 24개월은 검증되므로 해당 기간까지만 TCO 계산에 사용한다.
- `normal_price=NULL`로 실제 미확인을 표현한다. 0원이나 할인가와 같은 정상가로 채우지 않는다.
  원본 가격 미확인 마커와 확정 할인 기간이 모두 있어야 수집 검증을 통과한다.
- 정상가가 없는 평생 상품은 모든 유지기간에 확인된 월요금을 적용한다.
  기간 할인 상품은 선택한 유지기간이 할인 기간을 초과하면 추천에서 제외한다.
- 랭킹·비교·내 요금제에서 미확인 값을 정상가처럼 표시하지 않는다.
  DB 컬럼 변경 명령은 `python -m deploy.migrate_nullable_normal_price --apply`.
