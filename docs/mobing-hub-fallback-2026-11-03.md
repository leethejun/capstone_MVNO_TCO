# 모빙 알뜰폰허브 전체 수집

공식몰의 신규 HTTP 응답이 복구되지 않은 동안에도 모빙의 허브 공개 요금제를 제공하도록 전용 수집기를 추가했다. 허브가 유니컴즈에 연결하는 공개 브랜드관은 `https://www.mvnohub.kr/brand/plan/11.do`다. 해당 화면의 JavaScript가 호출하는 목록 API는 `/brand/plan/11.do/filter`이며 `.do`를 생략하면 404가 발생한다.

## 전체 수집 검증

2026년 11월 3일 확인한 허브 목록은 164개, 페이지당 12개, 총 14페이지다. API가 선언한 전체 수·페이지 수·현재 페이지·다음 페이지 여부를 검증하고, 각 페이지의 HTML 상품 ID 집합과 API를 대조한다. 상품 코드 중복, 빈 중간 페이지, 가격·기간 불일치, 목록 변경은 전체 실패로 처리한다.

상품별 상세 스펙 164개도 조회한다. 목록에는 빠진 일일 추가 데이터가 상세에서 18개 상품에 확인됐다. 상세의 기본 데이터와 일일 추가 용량, QoS, 통화·문자, 통신망을 사용한다. 숫자 없이 `Mbps`만 있는 빈 속도 표기는 속도 값으로 추정하지 않는다.

가격은 현재 납부액과 계약 할인 기간을 확인하고, 기간 종료 후 요금은 `기본료 - 상시 할인액`으로 계산해 화면과 대조한다. 예를 들어 상품 5549는 월 990원 12개월, 이후 20,000원이며 취소선 기본료 33,000원을 종료 후 요금으로 사용하지 않는다.

## 정기 작업과 장애 처리

관리자·정기 수집의 `DirectTelecomCrawler`가 공식몰 실패와 별개로 전용 허브 전체 수집기를 실행한다. 브랜드 목록 탐색에 문제가 생겨도 검증한 고정 공개 브랜드관 경로를 사용할 수 있다. 전체 스냅샷을 확인하면 모빙에 한해 전역 허브 수집 결과를 해당 스냅샷으로 대체해 중복과 누락을 방지한다.

관리자 상태는 `hub_fallback`, 공식몰 건수 0, 허브 전체 수집 건수와 `hub_complete`를 별도 표시한다. 공식몰 접속 문제는 복구된 것으로 표시하지 않는다. 공식몰과 허브 전체 수집이 동시에 실패하면 DB 교체 전에 전체 갱신을 중단해 기존 추천 목록을 보존한다.

## 모빙만 갱신

```bash
# 수집과 검증만 실행
docker exec alddle_backend python -B -m deploy.refresh_mobing_hub
# 백업 후 모빙 허브 상품만 갱신
docker exec alddle_backend python -B -m deploy.refresh_mobing_hub --apply
```

기존 공식몰 상품과 타 통신사는 변경하지 않는다. 가격이나 스펙이 바뀐 과거 허브 상품은 비활성 이력으로 보존하고, 동일한 상품을 재실행할 때는 기존 행을 재사용한다. 실행별 `runtime/mobing-hub-refresh-날짜시각/`에 원본 수집 결과·적용 전 DB·관리자 보고서 백업·실행 결과를 저장한다.

신규 회귀 테스트 8개를 포함한 백엔드 unittest 165개가 통과했다. 테스트는 할인 복원 요금, 일일 데이터 복원, 전체 페이지와 상세 조회, 부분 수집 거부, 공식몰 실패 시 허브 전환, 기존 이력·타 통신사 보존과 반복 실행을 검증한다.

## 운영 반영 결과

12시 22분 한국 시간 기준 새 HTTP 요청으로 전체 수집을 다시 완료한 후 164개를 삽입했다. 실행·백업 기록은 `runtime/mobing-hub-refresh-20261103-122206/`에 있다. 백엔드 컨테이너를 재시작해 관리자 및 정기 수집에도 적용했다.

- 운영 DB의 활성 모빙 상품 164개, 일일 추가 데이터가 있는 상품 18개.
- 6/12/48개월 모두 모빙 164개 전부 TCO 랭킹 계산 가능.
- 실제 6/12/48개월 랭킹 API 모두 HTTP 200. API 상한인 상위 100개 반환을 각각 확인.
- 관리자 API는 공식몰 0개, 허브 164개, 활성 164개, 상태 `hub_fallback`, `hub_complete=true`를 반환.
- 공식몰 장애는 그대로 명시하고 허브 전체 수집 완료를 별도 안내한다.
